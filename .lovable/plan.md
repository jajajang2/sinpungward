## 출석부 수정 계획

`src/pages/AttendancePage.tsx` 한 파일만 수정합니다.

### 1. 헤더 출석 요약 3분할 표시
현재 "전체 출석 N명 · 방문자 M명"을 다음과 같이 변경:

- **전체 출석: (회원 출석 수 + 방문자 수)명**
- **전체회원 출석: (회원 출석 수)명**
- **방문자: (방문자 수)명**

상단 카드(line 471~474)에 세 개의 작은 통계 칩을 가로로 배치합니다.

### 2. 캘린더 숫자 = 전체 출석 (회원+방문자)
`attendanceCountsByDate` (line 189~202)는 이미 회원 출석 + 방문자 수를 합산하고 있어 정상 동작합니다. 다만 라벨이 "N명"으로 표시되므로 그대로 두되, 1번 항목과 일관되게 "전체 출석" 기준임을 보장합니다. (코드 변경 없음, 확인만)

### 3. 방문자 입력 UX 개편 (데스크톱)
오른쪽 방문자 카드(line 566~610)를 다음과 같이 재구성:

```
┌─ 방문자 ──────────────┐
│ 방문자 N명             │
│ ┌─ 방문자 리스트 ──┐  │
│ │ • 이름 / 연락처   │  │
│ │ • 이름 / 연락처   │  │
│ └──────────────────┘  │
│ [+ 방문자 추가] 버튼   │
└──────────────────────┘
```

- 인라인 입력 폼(line 581~588) 제거
- 그 자리에 "방문자 추가" 버튼만 배치
- 버튼 클릭 시 새 다이얼로그(Dialog) 열림

### 4. 방문자 추가 다이얼로그 (신규)
데스크톱/모바일 공통으로 사용하는 다이얼로그:

- 입력 필드: 이름 / 연락처 / 메모
- 푸터 버튼 3개:
  - **닫기**: 저장하지 않고 닫음 (draft 초기화)
  - **추가 후 닫기**: 저장 → 성공 시 닫고 draft 초기화
  - **계속 추가**: 저장 → 성공 시 draft만 초기화하고 다이얼로그 유지 (다음 방문자 바로 입력 가능)

기존 `handleSaveVisitor`를 옵션 인자(`{ closeAfter: boolean }`)를 받도록 살짝 확장하거나, 두 개의 핸들러로 분리합니다.

### 5. 모바일 다이얼로그 통합
기존 모바일 전용 방문자 다이얼로그(line 613~655)도 위 신규 다이얼로그와 동일한 푸터(닫기 / 추가 후 닫기 / 계속 추가) 구조로 통일. 모바일에선 기존처럼 "방문자 입력" 버튼으로 같은 다이얼로그를 엽니다. 방문자 리스트는 다이얼로그 안에 함께 표시.

### 동작 요약
- 데스크톱: 오른쪽 패널에 카운트 + 리스트 + [방문자 추가] 버튼 → 클릭 시 다이얼로그
- 모바일: 상단 [방문자 입력] 버튼 → 동일 다이얼로그
- 다이얼로그 푸터: 닫기 / 추가 후 닫기 / 계속 추가

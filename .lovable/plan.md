## 원인

현재 불참석자 클릭은 `/members?memberId=...` 로 이동하고, `MembersPage`에서 이 URL 값을 읽어 `selectedMember`를 설정하는 방식입니다.

그런데 `MembersPage`의 URL 처리 로직이 회원을 찾은 직후 `memberId` 파라미터를 바로 삭제합니다. 이 과정에서 라우터 상태가 다시 바뀌고, 화면 전환/상태 반영 타이밍에 따라 선택된 회원 상세 패널이 유지되지 않고 기본 회원기록양식 화면으로 돌아갈 수 있습니다.

즉, 핵심 버그는 **URL 파라미터를 선택 상태로 완전히 반영하기 전에 같은 effect 안에서 URL을 다시 바꾸는 상태 경쟁 문제**입니다.

## 수정 계획

1. `MembersPage.tsx`의 `memberId` URL 처리 방식을 안정화합니다.
   - `memberId`가 있으면 회원 목록 로딩 후 해당 회원을 찾아 `selectedMember`로 설정합니다.
   - 동시에 `selectedGroupId`를 `all`로 설정해 데스크톱에서도 상세 패널 분기가 확실히 열리게 합니다.

2. `memberId` 파라미터를 즉시 삭제하지 않도록 변경합니다.
   - URL 파라미터를 유지하면 새로고침해도 같은 회원 카드가 열리고, 상태 경쟁이 사라집니다.
   - 다른 회원을 일반 목록에서 클릭하거나 뒤로 가기/그룹 변경 시에는 기존 UI 상태 흐름대로 동작하게 둡니다.

3. 필요하면 `selectedMember`가 URL의 `memberId`와 이미 같을 때 불필요한 상태 업데이트를 하지 않도록 가드를 추가합니다.

## 기대 결과

불참석자 이름을 클릭하면 `/members?memberId=해당ID`로 이동한 뒤, 회원기록양식의 기본 화면이 아니라 해당 회원의 실제 상세 카드가 바로 열립니다.
